# Stylint

Use `stylint` only when editing user-facing prose, Markdown, workshop lessons, public docs, articles, or publishable explanations generated by AI.

Do not use `stylint` for prose written and edited by the user, even when it is
an article or other public document. Also do not use it for internal engineering
documents, process docs, handoff docs, planning notes, or repo maintenance notes.

## Before Editing

Print the workflow for your stage and put every numbered step in your to-do
list:

```bash
stylint --workflow draft path/to/content   # new text
stylint --workflow edit path/to/content    # changes to existing text
```

If the task needs a specific guide, print it directly:

```bash
stylint --style-guide voice
stylint --style-guide formatting
stylint --style-guide code-style
stylint --style-guide polish
```

## Run Checks

Check the current project:

```bash
stylint
```

Check a specific folder or repo:

```bash
stylint path/to/content
```

Exclude folders or files that are outside the requested scope:

```bash
stylint path/to/content --exclude _docs --exclude AGENTS.md --exclude README.md
```

Use `--ignore` only for investigation. Do not use it as the final verification pass, because one edit can introduce a different kind of issue.

## Fix Findings

- Fix high-confidence mechanical findings first.
- Use judgment for long sentences, comma warnings, and list suggestions.
- Preserve meaning and intensity; do not make the text more excited than the source.
- Do not blindly turn every comma sentence into bullets. Use bullets only for real lists or steps.
- Prefer rewriting scaffold like `The result is...`, `Rule of thumb:`, or `The only question is:` into the direct sentence.

After editing, always run the full check again without `--ignore`:

```bash
stylint path/to/content
```

## Before Reporting Done

A passing static check is not the end. It covers mechanical rules only, and
the output's `Next:` footer says so. Before you report the text as done, run:

```bash
stylint --workflow final path/to/content
```

Then do every step it lists: run each smell prompt (`stylint --prompt NAME`)
in its own subagent, re-run the static check on the rewritten files, do the
polish read, and run the repo's own checks. Don't mark a smell pass done
unless a reviewer actually ran it and reported its changes.

## If Stylint Is Missing

If the checkout exists, install it into the shell path:

```bash
cd ~/git/stylint && ./install.sh
source ~/.bashrc
```

Inside the stylint checkout, this also works:

```bash
uv run stylint
```
